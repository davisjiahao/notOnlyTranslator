## Context

翻译链路横跨内容脚本、后台 Service Worker、供应商适配层和设置页。当前这些模块对批量请求结构、API 响应格式、凭证要求和活动配置的判断不一致，导致全页翻译、传统翻译供应商、自定义端点以及多配置切换在特定组合下失效。

这些问题不需要改变存储结构或对外消息类型，但需要统一边界处的数据契约，并让单条翻译和批量翻译复用相同的供应商能力判断。

## Goals / Non-Goals

**Goals:**

- 保证内容脚本发送的批量翻译请求始终符合后台契约。
- 让批量翻译与单条翻译采用一致的供应商、密钥和响应格式策略。
- 正确处理传统翻译供应商返回的纯文本。
- 修复全页右键菜单、自定义端点权限、活动配置和请求队列状态问题。
- 保持现有消息协议和持久化数据向后兼容。

**Non-Goals:**

- 不重构整个翻译架构或替换现有供应商 SDK。
- 不引入新的运行时依赖。
- 不调整翻译提示词、缓存上限或用户等级算法。
- 不迁移已有配置数据。

## Decisions

### 1. 在内容脚本边界统一构造批量请求

全页翻译和自动批量翻译必须发送相同的 `BatchParagraphRequest` 结构，包括稳定的 `id`、`text` 和 `elementPath`。后台仍保留运行时校验，使旧版本或异常发送方不能通过错误负载触发未捕获异常。

### 2. 按供应商响应类型选择批量策略

LLM 供应商继续使用一次请求返回结构化 JSON 的批量路径。Google 免费翻译、Google Cloud、Youdao 和 DeepL 等传统供应商按段落调用纯文本翻译路径，并在服务边界统一包装为 `TranslationResult`。Ollama 和免费 Google 翻译不再被通用 API Key 校验拦截。

这样保留 LLM 批处理效率，同时避免把传统供应商的纯文本交给 JSON 解析器。

### 3. 活动配置是供应商和凭证的唯一优先来源

只有当前活动供应商为 DeepL 时才走 DeepL 专用路径，非活动配置中的 DeepL 密钥不能改变路由。读取活动配置时同步应用主密钥和 `secondaryApiKey`，兼容 Baidu 等双凭证供应商；旧版顶层字段仍作为回退。

### 4. 自定义端点在用户操作期间申请主机权限

设置页测试或保存自定义端点前，将 URL 规范化为源站匹配模式并调用 `chrome.permissions.contains/request`。用户拒绝时返回明确错误，不发起网络请求。后台自动翻译阶段只使用已授予权限，避免在非用户手势中申请权限。

### 5. 请求队列始终使用真实请求 ID 收尾

批量请求 ID 在 `try` 块外保存。失败时使用与入队相同的 ID 调用队列失败处理，不再使用固定占位 ID，从而避免残留中的请求记录。

### 6. 右键菜单按菜单类型校验输入

“翻译选中文本”要求存在选中文本；“翻译整个页面”只要求有效标签页。两个分支分别校验，避免共享的提前返回吞掉全页操作。

## Risks / Trade-offs

- 传统供应商的批量模式会产生每段一次请求，吞吐量低于 LLM 批处理；这是保证协议正确性的保守选择，后续可在供应商支持批量接口时单独优化。
- 用户可能拒绝自定义主机权限；设置页需要保留原配置并展示可操作的错误信息。
- 对异常批量负载增加校验后，旧发送方会收到明确错误而不是后台异常；这是预期的兼容性收紧。
- 并行调用传统供应商可能触发限流，因此实现应沿用现有批次大小和错误降级机制，不额外扩大并发。

## Migration Plan

无需数据迁移。发布后读取现有活动配置时自动应用 `secondaryApiKey`。如需回滚，可直接回退代码；消息结构和存储字段均未新增强制项。
