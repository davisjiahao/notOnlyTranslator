## Why

当前自动批量翻译、全文翻译及部分供应商配置存在可复现的集成缺陷，导致默认无密钥模式、自定义 API、传统翻译供应商和多配置切换无法可靠工作。需要统一消息契约与供应商路由，并补齐权限和失败清理，避免核心翻译入口静默失效或留下脏状态。

## What Changes

- 统一全文翻译与批量翻译的请求结构，保证所有入口发送完整的段落 ID、文本、元素路径、翻译模式和页面 URL。
- 让批量翻译复用与单段翻译一致的供应商策略，支持免费 Google、Ollama、LLM 及传统翻译供应商。
- 修正 Google Cloud、有道等传统供应商的纯文本响应处理，避免按 LLM JSON 解析。
- 修正右键“翻译此页面”对选中文本的错误依赖。
- 在保存或测试自定义 API 端点前请求对应的可选主机权限，并对无效或被拒绝的端点给出明确失败结果。
- 仅在 DeepL 配置处于激活状态或混合翻译明确启用时使用 DeepL 主路径。
- 使用真实批量请求 ID 更新失败队列状态，并确保失败请求最终清理。
- 补齐多 API 配置中的辅助密钥传递，保证百度等双密钥供应商使用激活配置。

## Capabilities

### New Capabilities

- `translation-integration-reliability`: 规定各翻译入口、供应商路由、主机权限和持久化请求队列的一致行为。

### Modified Capabilities

无。

## Impact

- 影响后台消息路由、批量翻译服务、供应商选择、设置存储和内容脚本全文翻译入口。
- 影响选项页自定义 API 配置流程及 Manifest 可选主机权限的运行时申请。
- 不改变现有消息类型名称，但会严格化 `BATCH_TRANSLATE_TEXT` 的 payload 契约。
- 新增针对消息契约、无密钥批量翻译、传统供应商、激活配置和失败队列的回归测试。
