## 🔴 P0 — Must Fix (WCAG violations)

### 1. AchievementCard: Missing ARIA for achievement status
**File**: `AchievementCard.tsx:18-95`
**WCAG**: 4.1.2 Name, Role, Value
**Issue**: The card is a `<button>` but provides no accessible name describing the achievement state. Screen readers will announce the text content but not convey whether the achievement is locked/unlocked.
**Fix**: Add `aria-label` that includes achievement name and status:
```tsx
<button
  aria-label={`${achievement.name}${isUnlocked ? ' (已解锁)' : ' (未解锁)'}`}
  aria-describedby={`achievement-desc-${achievement.id}`}
>
```
Also add `id` to the description element:
```tsx
<p id={`achievement-desc-${achievement.id}`} className="text-xs ...">
```

### 2. TranslationStyleSettings: radiogroup missing aria-activedescendant
**File**: `TranslationStyleSettings.tsx:99-124`
**WCAG**: 1.3.1 Info and Relationships
**Issue**: The highlight style buttons use `aria-pressed` (toggle pattern) instead of `role="radio"` + `aria-checked` (radiogroup pattern). They are mutually exclusive choices — should be radio group.
**Fix**: Change to radiogroup pattern:
```tsx
<div role="radiogroup" aria-label="高亮样式">
  {options.map(opt => (
    <button
      role="radio"
      aria-checked={styleConfig.highlightStyle === opt.value}
      // ...
    />
  ))}
</div>
```

## 🟡 P1 — Should Fix (usability barriers)

### 3. TranslationHistory: delete button aria-label not unique
**File**: `TranslationHistory.tsx:353`
**WCAG**: 4.1.2 Name, Role, Value
**Issue**: Delete button aria-label uses `truncateText(entry.originalText, 30)` which may not be unique if entries have similar prefixes. Screen reader users may not distinguish between delete actions.
**Fix**: Include timestamp or unique identifier in the label.

### 4. TranslationStyleSettings: Custom CSS expand/collapse not announcing state
**File**: `TranslationStyleSettings.tsx:275-280`
**WCAG**: 4.1.2 Name, Role, Value
**Issue**: The "展开"/"收起" button changes its visible text but has no `aria-expanded` attribute. Screen readers won't know it's an expandable control.
**Fix**: Add `aria-expanded={showCustomCss}` to the button.

### 5. TranslationHistory: History entry cards use role="button" on clickable div
**File**: `TranslationHistory.tsx:311-317`
**WCAG**: 4.1.2 Name, Role, Value
**Issue**: `role="button"` on a `<div>` with `tabIndex={0}` is acceptable, but the accessible name is the entire text content which is very long. Should use `aria-label` for a concise label.
**Fix**: Add concise `aria-label` and consider making it a real `<button>`.

## 🟢 P2 — Nice to Have

### 6. FeedbackModal: radiogroup missing aria-activedescendant
**File**: `FeedbackModal.tsx:189-208`
**WCAG**: 1.3.1 Info and Relationships
**Issue**: The radiogroup has `role="radiogroup"` but no `aria-activedescendant` tracking. Individual radio buttons don't have `tabindex` management (should use roving tabindex pattern).
**Fix**: Implement roving tabindex for the radio group. First item has `tabIndex={0}`, others `tabIndex={-1}`.

### 7. WelcomeModalExperiment: LevelStep buttons not in radiogroup
**File**: `WelcomeModalExperiment.tsx:377-401`
**WCAG**: 1.3.1 Info and Relationships
**Issue**: Level selection buttons are mutually exclusive but lack `role="radiogroup"` wrapper and `role="radio"` on individual buttons.
**Fix**: Wrap in `<div role="radiogroup" aria-label="选择英语水平">` and add `role="radio"` + `aria-checked` to each button.

### 8. WelcomeModalExperiment: ApiStep provider buttons not in radiogroup
**File**: `WelcomeModalExperiment.tsx:521-565`
**WCAG**: 1.3.1 Info and Relationships
**Issue**: Same as #7 — provider selection buttons lack radiogroup semantics.
**Fix**: Same pattern as #7.

### 9. All modals: Missing escape key handler documentation
