## 一、保留并强化（已领先能力）

### 1.1 词汇等级判定 + 贝叶斯水平估算 🔒 护城河

| 项目 | 详情 |
|------|------|
| **问题** | 竞品普遍缺失此能力，但用户可能不理解其价值 |
| **方案** | 在 popup 增加"我的水平可视化"——展示用户当前等级、已掌握词数、最近增长趋势，让差异化**可见** |
| **投入** | M（2-3 天） |
| **预期影响** | 用户留存提升 15-20%，Chrome Store 好评增加 |
| **Owner** | 前端 |
| **CEO 决策** | ❌ 不需要 |

### 1.2 LLM 多引擎 + BYOK 模式 🔒 灵活性

| 项目 | 详情 |
|------|------|
| **问题** | 已支持 OpenAI/Anthropic/自定义，但切换体验不够流畅 |
| **方案** | 优化 API 切换 UI（已部分完成 ApiSwitcher），增加翻译质量对比提示，帮助用户选择最优引擎 |
| **投入** | S（1 天） |
| **预期影响** | 降低 API 配置门槛，提升高级用户满意度 |
| **Owner** | 前端 |
| **CEO 决策** | ❌ 不需要 |

### 1.3 无障碍合规 🔒 独家优势

## 二、补齐短板（按 ROI 排序）

### 2.1 发音功能 (TTS) ⭐ 最高 ROI

| 项目 | 详情 |
|------|------|
| **问题** | tooltip 中无法听发音，竞品普遍支持 |
| **方案** | 集成浏览器 Web Speech API（免费）或调用 TTS API，在 tooltip 增加发音按钮 |
| **投入** | S（1 天） |
| **预期影响** | 补齐基础学习功能，用户流失率降低 10% |
| **Owner** | 前端 |
| **CEO 决策** | ❌ 不需要 |

### 2.2 站点白名单/黑名单

| 项目 | 详情 |
|------|------|
| **问题** | 用户希望在特定网站（如 Gmail、网银）禁用扩展 |
| **方案** | 在 options 页面增加站点管理，支持通配符和正则表达式 |
| **投入** | S（1 天） |
| **预期影响** | 减少误翻译投诉，提升专业场景信任度 |
| **Owner** | 前端 |
| **CEO 决策** | ❌ 不需要 |

### 2.3 间隔重复/复习系统

| 项目 | 详情 |
|------|------|
| **问题** | 生词本只有收集功能，缺少复习闭环，无法与墨墨/Anki 竞争 |
| **方案** | **Phase 1**（轻量）：在生词本中增加"复习模式"，基于 Ebbinghaus 遗忘曲线定时提醒复习；**Phase 2**（深度）：集成 AnkiConnect，支持一键推送生词到 Anki |
| **投入** | Phase 1: M（3-4 天）, Phase 2: M（3-4 天） |
| **预期影响** | 显著提升学习闭环完整性，降低流失到 Anki 组合的概率 |
| **Owner** | 前端 + CTO |
| **CEO 决策** | ❌ 不需要 |

### 2.4 Firefox / Safari 适配

| 项目 | 详情 |
|------|------|
| **问题** | 仅支持 Chrome/Edge，Firefox 用户（开发者群体）和 Safari 用户（Mac/iPhone）无法使用 |
| **方案** | Firefox 适配成本低（Manifest V3 兼容），优先做；Safari 需要单独开发 Web Extension |
| **投入** | Firefox: S（2 天）, Safari: L（1-2 周） |
| **预期影响** | Firefox 扩覆盖 5-10% 用户，Safari 可打通 iOS 场景 |
| **Owner** | CTO |
| **CEO 决策** | ✅ Safari 投入较大，需确认优先级 |

## 三、战略放弃（不做）

### 3.1 整页翻译 / 双语对照 ❌

| 项目 | 详情 |
|------|------|
| **原因** | 这是沉浸式翻译的主战场，技术投入大、翻译成本高、与"按水平翻译"定位冲突 |
| **替代策略** | 专注"精准翻译少量难词"，而不是"翻译全篇内容"，这是差异化而非劣势 |
| **用户沟通** | 在 FAQ 中说明设计理念："我们不是翻译整篇文章的工具，而是帮助你在阅读中学习的伙伴" |

### 3.2 独立翻译引擎 ❌

| 项目 | 详情 |
|------|------|
| **原因** | 自建翻译模型成本极高（训练 + 推理），DeepL/Google/OpenAI 已经做得足够好 |
| **替代策略** | 继续做 BYOK 多引擎聚合，让用户选择最优翻译服务 |

### 3.3 社交功能 ❌

| 项目 | 详情 |
|------|------|
| **原因** | 产品线不相关，增加复杂度和维护成本，用户核心需求是学习不是社交 |
| **替代策略** | 如需要社区运营，通过 WeChat/Discord 等外部平台而非内置功能 |

## 四、0→1 创新机会

### 4.1 阅读难度自适应 🔮 差异化杀手功能

| 项目 | 详情 |
|------|------|
| **想法** | 用户打开一个页面，扩展自动评估页面难度（如 CET-4/6/IELTS/TOEFL 等级），并建议"这个页面大约有 23 个词超出你的水平" |
| **方案** | 基于已标记词库 + 页面词频分析，生成页面难度报告。用户可以选择"只看超出水平的词"或"学习某个难度区间的词" |
| **投入** | M（3-5 天） |
| **预期影响** | 全球唯一"页面难度评估 + 按水平翻译"的组合，极大利器 |
| **Owner** | CTO |
| **CEO 决策** | ❌ 不需要 |

### 4.2 学习里程碑 + 成就系统 🏆

| 项目 | 详情 |
|------|------|
| **想法** | 用户在阅读中自然积累词汇，系统解锁里程碑（"你已掌握 500 词！""连续阅读 7 天"），给予正向反馈 |
| **方案** | 基于已有用户档案数据，设计 10-15 个里程碑类型，在 popup 展示进度条和成就徽章 |
| **投入** | M（3-4 天） |
| **预期影响** | 提升留存和日活，增加用户分享意愿（口碑传播） |
| **Owner** | 前端 |
| **CEO 决策** | ❌ 不需要 |

### 4.3 场景化词包 📚

| 项目 | 详情 |
|------|------|
| **想法** | 提供预置词包（"技术阅读"、"商务邮件"、"学术论文"、"旅游英语"），用户可以选择学习目标领域，系统优先标记该领域词汇 |
| **方案** | 基于领域词库 + 用户当前水平，智能推荐学习路径 |
| **投入** | M（词库整理 2 天 + 功能开发 2 天） |
| **预期影响** | 从"通用学习"扩展到"场景学习"，覆盖更多用户意图 |
| **Owner** | 前端 + CTO |
| **CEO 决策** | ❌ 不需要 |

### 4.4 移动端 Companion App 🔮

| 项目 | 详情 |
|------|------|
| **想法** | 浏览器扩展负责收集生词，手机 App 负责复习——打通"网页阅读 → 收集 → 碎片时间复习"的完整闭环 |
| **方案** | **Phase 1**: PWA 网页版复习工具（低投入）；**Phase 2**: React Native 原生 App |
| **投入** | Phase 1: M（1 周）, Phase 2: L（4-6 周） |
| **预期影响** | 覆盖移动端场景，显著提升日活和留存 |
| **Owner** | CTO + 前端 |
| **CEO 决策** | ✅ Phase 2 需要确认战略投入 |

## 六、风险与缓解

| 风险 | 影响 | 缓解策略 |
|------|------|---------|
| 沉浸式翻译加入"难度分级"功能 | 核心差异化被削弱 | 加速迭代阅读难度自适应 + 场景词包，保持领先 |
| Chrome Manifest V3 限制增强 | 功能受限 | 跟随 Chrome 规范，提前适配 |
| API 成本增长 | 用户体验/盈利受压 | 缓存优化 + 用户 BYOK + 免费额度管理 |
| 用户增长慢 | 产品无法验证 | 先做好核心体验，再通过 Chrome Store 优化和社区推广 |

---

## 七、需 CEO 决策事项

1. **Firefox / Safari 适配优先级**：Firefox 投入小、建议立即做；Safari 投入大、建议评估 Mac 用户占比后决定
2. **移动端战略**：Phase 1 PWA 低投入可做；Phase 2 原生 App 需要确认是否作为 2027 战略方向
3. **商业化时间表**：当前完全免费，何时引入 Pro 订阅？建议在用户基数达 10000+ 后评估
